# Online Shop

Order management system for an e-commerce process, developed as part of CSS-3008 Corporate Development labs.

## Project Overview

Online Shop manages orders through a controlled lifecycle. It demonstrates business rule validation, Spring Boot dependency injection, JPA/Hibernate persistence, Flyway migrations, a REST contract, and transaction management.

**Order lifecycle:**

`CART → PAID → SHIPPED → DELIVERED`

A return is handled as a separate process.

## Business Rules

| From | To | Allowed? |
|---|---|---|
| `CART` | `PAID` | Yes |
| `PAID` | `SHIPPED` | Yes |
| `DELIVERED` | `RETURNED` | No |
| `SHIPPED` | `CART` | No |

### Forbidden Transitions

1. **`DELIVERED → RETURNED`** — A delivered order cannot be returned directly. It must go through a separate return process.
2. **`SHIPPED → CART`** — A shipped order is already in logistics and cannot be moved back to the cart.

## Architecture

The project separates business rules, application logic, persistence, HTTP, and outbound integrations.

- **`domain`** — Order statuses, identifiers, business rules, and domain exceptions. Plain Java: no Spring, no `ResponseEntity`, no `jakarta.validation`.
- **`handler`** — REST controller, request/response/error records, exception advice, and application service.
- **`persistence`** — JPA entity, Spring Data repository, and adapter. Jackson never sees the entity.
- **`outbound`** — Outbound ports/adapters (notifier). Downstream URL and timeout come from yaml.
- **`config`** — Application entry point and Spring bean configuration.

`OrderPolicy` is the earlier all-in-one rule object (labs 1–2). `Rule` / `TransitionRule` / `ForbiddenRule` / `RuleChain` is the later SOLID version used by `OrderService`.

### REST (Lab 4)

- `POST /api/v1/orders` — create one order → `201` + `Location`
- `GET /api/v1/orders/{id}` — read by UUID → `200`
- Failures use `{ code, message, correlationId }` (`VALIDATION` / `NOT_FOUND` / `DUPLICATE` / …)
- OpenAPI UI: `/swagger-ui.html`
- Health: `/actuator/health` (only `health` and `info` are exposed)

### Spring Integration

`Application` starts the Spring Boot application and scans `org.example`.

`OrderService` is a Spring `@Service` with constructor injection. The `Rule` bean is configured in `Config` as a `RuleChain`.

## Database and Persistence

PostgreSQL stores orders in the `shop_order` table. Start it with:

```bash
docker compose up -d
```

The schema is owned by Flyway:

`src/main/resources/db/migration/V1__create_shop_order.sql`

Hibernate uses `ddl-auto: validate`. `baseline-on-migrate: true` supports a DB that already has `shop_order` from earlier labs.

| Column | Purpose |
|---|---|
| `id` | UUID primary key |
| `business_key` | Unique business identifier for an order |
| `status` | Current order status (stored as text) |
| `title` | Order title |
| `created_at` | Creation timestamp generated by PostgreSQL |

Constraints: `PRIMARY KEY`, `UNIQUE(business_key)`, `NOT NULL`, `CHECK` on known statuses.

A duplicate business key becomes domain `DuplicateOrder` (`SQLState 23505`).

## Configuration / Profiles

- `application.yaml` — shared settings (JPA, Flyway, error leak off, actuator). No DB password.
- `application-dev.yaml` — localhost PostgreSQL `css`/`css`, downstream `http://localhost:9090`, timeout `2s`
- `application-prod.yaml` — `CSS_DB_URL` / `CSS_DB_USER` / `CSS_DB_PASSWORD` (and downstream env vars)

`spring.profiles.default: dev`
